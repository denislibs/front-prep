# JavaScript-фундамент: что спрашивают у сеньоров

Формат: вопрос → эталонный ответ уровня сеньора (коротко, но с глубиной). Проверяй себя: закрой ответ и ответь вслух.

## Event Loop

**Вопрос: как работает event loop? Чем микрозадачи отличаются от макрозадач?**

Ответ: JS однопоточный, конкурентность строится на цикле событий. За один «тик»:
1. Выполняется одна **макрозадача** (script, setTimeout, setInterval, I/O, события).
2. После неё выполняется **вся очередь микрозадач** до опустошения (`Promise.then/catch/finally`, `queueMicrotask`, `MutationObserver`). Если микрозадача порождает микрозадачу — та тоже выполнится в этом же тике.
3. При необходимости — рендеринг (rAF-колбэки выполняются перед отрисовкой кадра).

Классическая задача:
```js
console.log(1);
setTimeout(() => console.log(2), 0);
Promise.resolve().then(() => console.log(3));
console.log(4);
// 1, 4, 3, 2  — микрозадачи (then) раньше макрозадач (setTimeout)
```

Сеньорский нюанс: длинная синхронная работа или бесконечный поток микрозадач блокирует рендеринг → фризы UI. Разбивать через `setTimeout`/`scheduler.postTask`/`requestIdleCallback`, тяжёлое — в Web Worker.

## Замыкания

**Вопрос: что такое замыкание и где вы реально его используете?**

Функция + её лексическое окружение: функция «помнит» переменные из области, где была создана, даже после выхода из неё. Практика: колбэки и обработчики, каррирование, приватное состояние (модули, фабрики), мемоизация, debounce/throttle, хуки React (stale closure — типичный баг: колбэк «запомнил» старое значение стейта).

Классика с циклом:
```js
for (var i = 0; i < 3; i++) setTimeout(() => console.log(i)); // 3, 3, 3
for (let i = 0; i < 3; i++) setTimeout(() => console.log(i)); // 0, 1, 2 (let — новая привязка на итерацию)
```

## Прототипы

**Вопрос: как работает прототипное наследование?**

У каждого объекта есть скрытая ссылка `[[Prototype]]` (доступ через `Object.getPrototypeOf` / `__proto__`). При чтении свойства, которого нет на объекте, поиск идёт вверх по цепочке прототипов. `class` — синтаксический сахар над этим механизмом: методы попадают в `ClassName.prototype`. `new Fn()` создаёт объект с прототипом `Fn.prototype` и вызывает `Fn` с `this` на нём.

Отличия: `Object.create(proto)` — прямое создание с заданным прототипом; стрелочные функции не имеют `prototype` и не могут быть конструкторами.

## this

**Вопрос: как определяется `this`?**

Определяется **в момент вызова**, по 4 правилам (в порядке приоритета):
1. `new Fn()` — this = новый объект.
2. `fn.call/apply/bind(ctx)` — явная привязка.
3. `obj.fn()` — объект перед точкой.
4. Просто `fn()` — `undefined` в strict mode, `globalThis` без него.

Стрелочные функции `this` не имеют — берут из внешней лексической области (поэтому удобны в колбэках). Потеря контекста: `const m = obj.method; m()` — this потерян; лечится `bind` или стрелкой.

## Промисы и async/await

**Вопрос: состояния промиса, отличия комбинаторов?**

Состояния: pending → fulfilled | rejected (переход один раз, необратим).
- `Promise.all` — все успешны, либо reject при первой ошибке (остальные не отменяются!).
- `Promise.allSettled` — ждёт все, отдаёт массив статусов; для независимых запросов.
- `Promise.race` — первый завершившийся (успех или ошибка); для таймаутов.
- `Promise.any` — первый успешный; AggregateError, если все упали.

`async/await` — сахар над промисами; `await` разрезает функцию на микрозадачи. Ошибки ловятся `try/catch`. Частая ошибка: последовательные `await` там, где можно параллельно (`await Promise.all([...])`).

**Отмена**: промисы не отменяются; используем `AbortController` — передаём `signal` в `fetch`, по `controller.abort()` fetch reject-ится с `AbortError`. В React — отмена в cleanup-функции `useEffect`.

## Типы, сравнение, копирование

- `typeof null === 'object'` (историческая ошибка), `typeof NaN === 'number'`, `NaN !== NaN` (проверять `Number.isNaN`).
- `==` делает приведение типов, `===` — нет. На собесе: `[] == ![]` → `true` (ко всеобщему ужасу).
- Примитивы копируются по значению, объекты — по ссылке.
- Поверхностная копия: спред `{...obj}`, `Object.assign`. Глубокая: `structuredClone(obj)` (нативно; не копирует функции), либо рекурсивно вручную (частая задача лайвкодинга — см. 05-livecoding).

## Область видимости, hoisting

- `var` — функциональная область, hoisting с `undefined`. `let/const` — блочная, temporal dead zone (обращение до объявления → ReferenceError).
- Function declaration поднимается целиком, function expression — нет.

## Сборка мусора и утечки памяти

Алгоритм — reachability (mark-and-sweep): недостижимое из корней удаляется. Типичные утечки во фронтенде: забытые таймеры и подписки (нет cleanup в `useEffect`), замыкания, держащие большие структуры, отсоединённые DOM-узлы, хранимые в JS, бесконечно растущие кеши. `WeakMap`/`WeakRef` не мешают сборке — для метаданных объектов.

## Модули

ESM (`import/export`): статический анализ → tree-shaking, top-level await, всегда strict mode, асинхронная загрузка. CommonJS (`require`): динамический, синхронный, значения копируются при экспорте примитивов. Динамический `import()` возвращает промис — основа code splitting.

## Итераторы и генераторы

Протокол итератора: объект с `next()` → `{value, done}`. `Symbol.iterator` делает объект iterable (`for..of`, спред). Генераторы (`function*`, `yield`) — простой способ писать итераторы, ленивые последовательности; исторически — основа корутин (redux-saga).
