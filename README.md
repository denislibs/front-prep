# Подготовка к собеседованию: Senior Frontend

Тренажёр и конспекты для подготовки к собеседованию на позицию senior frontend разработчика (React / Next.js).

**Тренажёр:** https://denislibs.github.io/front-prep/
**Конспекты:** https://denislibs.github.io/front-prep/notes/ — те же материалы для чтения: страница на вопрос, поиск по всему, лёгкие страницы для телефона

## С чего начать

1. Открой тренажёр по ссылке выше или локальный `index.html` в браузере.
2. Пройди план из [PLAN.md](PLAN.md) — шесть дней с конкретными темами на каждый.
3. Отвечай **вслух**. На интервью проваливаются на формулировках, а не на знаниях.

## Что внутри тренажёра

- **Лайвкодинг с автотестами** — пишешь решение в редакторе прямо на странице и запускаешь. Тесты показывают не «неверно», а что именно не работает: не отменяется предыдущий таймер, теряется контекст вызова, не ограничивается параллелизм. Код выполняется в изолированной песочнице, зацикливание останавливается по таймауту. Подсказки открываются по одной, чтобы подсмотреть направление, а не готовый ответ.
- **Карточки** — вопросы с ответами уровня сеньора по разделам. У большинства есть блок «Что добавит очков»: нюанс, который отличает выученный ответ от понятого.
- **Свободный ответ с разбором** — пишешь ответ своими словами, и его оценивает Claude по критериям карточки: что названо верно, что упущено, где формулировка поплыла и как это сказал бы сеньор. Работает там, где приложению доступна такая возможность; иначе блок просто не показывается.
- **Тесты** — вопрос и четыре варианта: здесь нельзя схитрить перед собой, как с карточками. После ответа сразу разбор, почему верный вариант верный и в чём подвох неверного. Ошибка автоматически отправляет соответствующую карточку на повтор, в итогах — список ошибок с переходом к подробному разбору.
- **Мок-интервью** — сессия из 5–30 вопросов подряд с таймером на каждый, приоритет отдаётся незакрытым темам. В конце — итоги и список того, что ушло на повтор.

Прогресс — статусы карточек, решённые задачи, написанный код и свои истории — сохраняется в браузере.

Сборка делает две версии страницы. Для Pages тяжёлые библиотеки вынесены в `assets/` и грузятся по требованию: React с транспайлером (1.2 МБ) приезжает только когда запускаешь задачу с DOM или React, редактор — при первом заходе в лайвкодинг. Для артефакта собирается самодостаточная версия, где всё внутри одного файла.

**Вопросы отсортированы по частоте.** Внутри каждой колоды сначала идёт то, что спрашивают почти на каждом интервью, в конце — редкая экзотика. У карточки видна метка: «спрашивают часто», «регулярно» или «редкий вопрос», а фильтр «Частые» оставляет только обязательный минимум. Если до собеседования пара дней — проходи сверху вниз и не трать время на хвост.

В разделе «Карточки» есть переключатель «Карточка / Список»: список показывает все вопросы колоды сразу, с отметками пройденного, и открывает любой по клику — при 85 карточках листать по одной незачем.

Горячие клавиши подсказаны прямо в панели карточки и меняются по ситуации: `Space` показать ответ, `1` на повтор, `2` знаю, стрелки листать, `1`–`4` выбрать вариант в тесте, `Ctrl/Cmd + Enter` запустить код.

```
status.js             сводка по контенту и контроль потери карточек

src/sandbox/          песочница: окружение проверок, DOM-хелперы, исполнитель
src/vendor/           собранные библиотеки (редактор кода, React, транспайлер JSX)
docs/spec-sandbox.md  контракт песочницы: формат автотестов и доступные проверки
docs/answer-style.md  стандарт ответа на карточке

research/quiz-*.js    тестовые вопросы с вариантами ответа

dist/                 собранный сайт (делается в CI, в git не хранится)
.github/workflows/    сборка и публикация на Pages

01-javascript.md      первоначальные конспекты, написанные до расширения;

03-react.md
04-browser-network.md
05-livecoding/
06-system-design.md
07-behavioral.md
```

## Как дополнять материал

Контент лежит отдельно от приложения, поэтому добавить свои вопросы просто.

Найди нужный файл в `research/` и добавь элемент в массив:

```js
{ id: 'jsx66',
  q: 'Текст вопроса?',
  a: `<p>Ответ. Разрешены теги <code>p ul ol li code strong br</code>.</p>`,
  code: `const example = 1;`,
  tip: 'Что добавит очков на собеседовании.' },
```

Внутри строк в обратных кавычках нельзя использовать саму обратную кавычку и последовательность `${` — в примерах кода вместо шаблонных литералов пиши конкатенацию.

Затем пересобери:

```bash
node build.js && node export-notes.js
```

Сборка проверит синтаксис каждого файла, найдёт повторяющиеся идентификаторы и провалидирует итоговый JavaScript, так что битый контент до приложения не доедет. Прогресс прохождения при пересборке не теряется — он привязан к идентификаторам карточек.

### Автотесты к задачам

Наборы проверок лежат в `research/tests-*.js`, их контракт описан в [docs/spec-sandbox.md](docs/spec-sandbox.md). После правок обязательно прогони:

```bash
node verify-tests.js
```

Он выполняет каждый набор против эталонного решения задачи. Требуемый результат — `0 с проблемами`: тест, который валит правильный ответ, хуже, чем отсутствие теста. Для проверки наборов с DOM и React нужны devDependencies (`npm install`), они уже прописаны в package.json.

### Публикация

Публикация автоматическая: пуш в `main` запускает сборку в GitHub Actions, которая собирает тренажёр, прогоняет автотесты задач, генерирует конспекты и выкладывает всё на Pages. Тренажёр попадает на корень, конспекты — в `/notes/`.

```bash
node build.js && git add -A && git commit -m "обновил тренажёр" && git push
```

Локально сайт конспектов собирается так:

```bash
node build.js && node export-notes.js && npx vitepress build notes-src
```

Синхронизации прогресса между устройствами на Pages не будет — она работает только в опубликованном артефакте. Прогресс сохраняется в локальном хранилище браузера. Проверка развёрнутых ответов через Claude там тоже недоступна: блок свободного ответа просто не показывается, остальное работает.
