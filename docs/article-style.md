# Каким должна быть статья

Статьи закрывают то, что карточками не закрыть: механику и связи между темами. Карточка отвечает на вопрос, статья объясняет, почему ответ такой.

Эталон — `articles/browser-rendering-event-loop.md`. Открой его и посмотри, прежде чем писать.

## Кому пишем

Разработчику с коммерческим опытом, который в теме плавает. Он знает слова, но не знает механики: слышал про событийный цикл, но не объяснит, почему `.then` обгоняет `setTimeout`. Значит:

- **Каждый термин объясняется при первом появлении.** Даже «поток», «стек», «ссылка». Одно-два предложения простыми словами, без «как известно».
- **Никакой снисходительности.** Не «это элементарно», а «здесь легко ошибиться, потому что…».
- **Простые слова вместо академических.** «Функция помнит переменные из места, где её создали» лучше, чем «замыкание захватывает лексическое окружение» — но второе тоже дай, потому что на интервью прозвучит именно оно.

## Объём и структура

**2500–4000 слов.** Меньше — получится расширенная карточка, больше — не дочитают.

```markdown
---
title: "Заголовок статьи"
---

# Заголовок статьи

Вводный абзац: что за тема, почему с ней сложно, что читатель будет уметь после.

## Часть 1. Название

Текст с подзаголовками третьего уровня внутри.

### Подтема

...

## Что спросят на интервью

Вероятные формулировки вопросов и краткие ответы.

## Коротко, для повторения

Нумерованный список тезисов на 6–10 пунктов.
```

Две последние секции обязательны — материал готовит к интервью, а не просто просвещает.

## Требования к содержанию

1. **Механика, а не перечисление.** Не «есть такие методы», а «что происходит внутри и почему сделано так».
2. **Примеры кода короткие и по делу.** Показывают контраст «ломается / работает» или разбирают вывод по шагам. Комментарии внутри кода объясняют неочевидное.
3. **Разбор пошагово там, где есть порядок выполнения.** Пронумерованные шаги с указанием, что в этот момент лежит в очереди или на стеке.
4. **Подводные камни из практики.** То, на чём реально спотыкаются, а не выдуманные крайние случаи.
5. **Связи с другими темами.** Ссылайся на соседние статьи и карточки: `[как работает браузер](./browser-rendering-event-loop)`.
6. **Никакой воды.** Без «в современном мире фронтенда», «давайте разберёмся», «как мы уже знаем».

## Схемы

Схема нужна там, где есть структура или порядок: дерево, конвейер, очередь, цепочка вызовов. Если схема просто повторяет текст — не рисуй.

Рисуем инлайновым SVG внутри `<figure class="diagram">`. Цвета берём переменными темы, чтобы схема читалась и в светлом, и в тёмном оформлении:

```html
<figure class="diagram">
<svg viewBox="0 0 600 160" role="img" aria-label="Описание схемы для скринридера">
  <style>
    .d-box { fill: var(--vp-c-bg-soft); stroke: var(--vp-c-divider); stroke-width: 1.5; }
    .d-hot { stroke: var(--vp-c-brand-1); stroke-width: 2; }
    .d-t { fill: var(--vp-c-text-1); font: 700 13px/1 ui-sans-serif, system-ui, sans-serif; }
    .d-s { fill: var(--vp-c-text-2); font: 400 11px/1 ui-sans-serif, system-ui, sans-serif; }
    .d-a { stroke: var(--vp-c-text-3); stroke-width: 1.5; fill: none; }
  </style>
  <defs>
    <marker id="ah-УНИКАЛЬНОЕ-ИМЯ" markerWidth="8" markerHeight="8" refX="7" refY="4" orient="auto">
      <path d="M0 1 L7 4 L0 7" fill="none" stroke="var(--vp-c-text-3)" stroke-width="1.5"/>
    </marker>
  </defs>

  <rect class="d-box" x="20" y="40" width="160" height="60" rx="2"/>
  <text class="d-t" x="100" y="66" text-anchor="middle">Заголовок</text>
  <text class="d-s" x="100" y="86" text-anchor="middle">пояснение</text>

  <path class="d-a" d="M184 70 H216" marker-end="url(#ah-УНИКАЛЬНОЕ-ИМЯ)"/>
</svg>
<figcaption>Подпись объясняет, что важно увидеть на схеме.</figcaption>
</figure>
```

Правила: `viewBox` обязателен (схема тянется по ширине), `role="img"` и `aria-label` обязательны, идентификатор маркера стрелки должен быть уникальным в пределах статьи. Две-четыре схемы на статью достаточно.

## Критично: экранирование

Сайт собирается VitePress, который разбирает markdown как шаблон Vue. Угловая скобка в обычном тексте ломает сборку.

- Любой тег, дженерик или сравнение в тексте — **только в обратных кавычках**: `` `<div>` ``, `` `Array<T>` ``, `` `a < b` ``.
- Вне кавычек пиши `&lt;` и `&gt;`.
- Двойные фигурные скобки `{{` в тексте недопустимы — Vue примет их за подстановку.
- Внутри блоков кода ограничений нет: там всё безопасно.

Проверка: собери сайт и убедись, что ошибок нет.
