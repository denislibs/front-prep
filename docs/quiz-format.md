# Формат тестовых вопросов

Тест — это проверка с вариантами ответа, где нельзя схитрить перед собой: либо знаешь, либо нет. Карточки тренируют формулировку, тест ловит пробелы.

## Структура элемента

```js
const QUIZ_A = [
  { id: 'qa1',
    deck: 'js',
    q: 'Что выведет этот код?',
    snippet: `console.log(typeof null);`,
    options: [
      "'object'",
      "'null'",
      "'undefined'",
      'выбросит TypeError',
    ],
    correct: 0,
    why: `<p><strong>typeof null === 'object'</strong> — историческая ошибка первой реализации языка: у значений тег типа хранился в младших битах, и у null он совпал с тегом объекта. Исправлять не стали, потому что это сломало бы существующий код.</p>
    <p>Вариант <code>'null'</code> выглядит логичным, но такой строки <code>typeof</code> не возвращает никогда.</p>`,
    cardId: 'jsx14' },
];
```

## Поля

- `id` — уникален в пределах файла, префикс по файлу (`qa1`, `qb1`, `qc1`).
- `deck` — к какой колоде относится: `js`, `ts`, `react`, `css`, `web`, `sd`.
- `q` — вопрос. Может отличаться от вопроса карточки: тест требует более точной постановки с однозначным ответом.
- `snippet` — необязательный код к вопросу. Показывается вместе с вопросом.
- `options` — **ровно четыре** варианта.
- `correct` — индекс верного варианта, от 0 до 3. **Раскидывай верные ответы равномерно**: не должно получиться так, что верный почти всегда первый.
- `why` — разбор после ответа: почему верный вариант верен и **почему самый привлекательный неверный — неверен**. Это главная ценность теста, не экономь здесь. Разрешены теги `p ul ol li code strong br`.
- `cardId` — id карточки, где тема разобрана подробно. Пользователь сможет перейти к ней из разбора.

## Требования к качеству

1. **Отвлекающие варианты — это распространённые заблуждения**, а не случайный мусор. Плохо: «выбросит TypeError» там, где ничего похожего быть не может. Хорошо: ответ, который человек даст, если знает тему наполовину.
2. **Ровно один верный вариант.** Никаких «всё перечисленное» и «ни один из вариантов».
3. **Варианты одинаковы по форме и длине.** Если верный вариант вдвое длиннее и подробнее остальных — его видно без знания темы.
4. **Проверяй понимание, а не память о формулировке.** Лучший вопрос — про поведение кода или про выбор решения в ситуации, а не «как называется приём».
5. **Никаких вопросов с подвохом ради подвоха.** Тест готовит к интервью, а не унижает.
6. Вопросы на код особенно ценны: дай `snippet` и спроси, что выведет или где ошибка.

## Экранирование

Внутри строк в обратных кавычках нельзя использовать саму обратную кавычку и последовательность `${`. В коде вместо шаблонных литералов пиши конкатенацию строк. В `options` кавычки внутри строк экранируй или используй разные типы кавычек.
