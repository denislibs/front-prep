# Frontend System Design

На сеньорских интервью проверяют не «правильный ответ», а **структуру мышления**: сбор требований → трейд-оффы → обоснованные решения. Молчаливый идеальный дизайн проигрывает проговорённому среднему.

## Фреймворк ответа — RADIO (45 минут)

1. **Requirements (~5 мин)** — уточнить, не бросаться решать:
   - Функциональные: какие ключевые сценарии? (для ленты: просмотр, лайк, пост, комментарии?)
   - Нефункциональные: аудитория и устройства (mobile?), SEO нужен?, офлайн?, i18n/RTL?, доступность, поддерживаемые браузеры, масштаб (сколько элементов/пользователей).
2. **Architecture (~10 мин)** — крупные блоки и их связи: клиент (страницы/виджеты), слой данных (стор, кеш), API-слой, сервер (SSR?), CDN. Нарисовать схему словами/боксами.
3. **Data model (~10 мин)** — сущности, их поля, где живут (серверный кеш vs клиентский стейт), нормализация (byId + ids), что в URL.
4. **Interface / API (~10 мин)** — контракт с бэком: REST vs GraphQL, форма пагинации, форматы ошибок; интерфейсы ключевых компонентов (props).
5. **Optimizations (~10 мин)** — производительность (загрузка, рендеринг), UX-состояния (loading/error/empty/offline), доступность, безопасность. Здесь сеньор отличается от мидла — говорить про трейд-оффы.

## Ключевые темы-кирпичики (переиспользуются во всех задачах)

**Пагинация**: offset (просто, но дубли/пропуски при вставках, дорогие большие offset) vs **cursor** (стабильна для лент, нет произвольной страницы). Бесконечный скролл: IntersectionObserver + виртуализация списка (в DOM только видимое окно).

**Кеширование и данные**: TanStack Query/SWR — stale-while-revalidate, инвалидация по ключам, refetch on focus. Нормализация, чтобы лайк в ленте обновился и в открытом посте.

**Оптимистичные обновления**: применить изменение в UI сразу, при ошибке — откатить + тост. Обязательно упомянуть в любой задаче с мутациями (лайки, корзина).

**Realtime**: polling / SSE / WebSocket — выбор от направления и частоты (см. 04-browser-network.md).

**Рендеринг**: SSR/SSG/ISR/CSR по типу страницы; продукт — публичный (SEO → SSR/ISR) или залогиненный дашборд (CSR/streaming).

**Состояния UI**: скелетоны, error + retry, пустые состояния, офлайн. Race conditions при быстрых переключениях (отмена запросов).

**Доступность**: семантика, фокус-менеджмент (модалки — focus trap, возврат фокуса), aria-live для динамики, клавиатура полностью.

## Разбор 1: Лента новостей (Facebook-style)

- Требования: бесконечная лента, лайки/комменты, создание поста; mobile-first; миллионы пользователей.
- Архитектура: SSR первого экрана (быстрый LCP) + CSR-дозагрузка; App-слой: FeedList, PostCard, Composer; данные — TanStack Query.
- Данные: cursor-пагинация (`GET /feed?cursor=...&limit=20`), нормализованный кеш постов, автор — вложенный объект или отдельный кеш users.
- Оптимизации: виртуализация ленты; `content-visibility`/окно рендера; изображения lazy + srcset + фикс. aspect-ratio (CLS!); оптимистичный лайк; prefetch следующей страницы при приближении к концу; композер — code-split (тяжёлый редактор грузим по клику).

## Разбор 2: Автокомплит / поисковые подсказки

- Требования: латентность < ~100мс восприятия, тысячи запросов, клавиатурная навигация.
- Клиент: debounce 150–300мс; отмена предыдущего запроса (AbortController) — защита от гонок; минимум 2 символа; кеш запрос→результаты (LRU); подсветка совпадения.
- UX/a11y: combobox-паттерн ARIA (`role="combobox"`, `aria-expanded`, `aria-activedescendant`), Escape закрывает, Enter выбирает.
- Обсудить: кеш на CDN для популярных префиксов, показ последних/популярных запросов при пустом инпуте.

## Разбор 3: Дашборд с графиками / таблица на 100k строк

- Виртуализация строк и колонок; серверная сортировка/фильтрация vs клиентская (порог ~10k строк); web worker для агрегации; мемоизация ячеек; дебаунс фильтров; состояние таблицы в URL (шаринг ссылки).

## Разбор 4: Чат

- WebSocket + fallback; статусы сообщения (sending → sent → read) через optimistic UI + подтверждение сервером; упорядочивание и дедупликация по clientId; история — cursor-пагинация вверх; офлайн-очередь отправки; непрочитанные и уведомления.

## Инфраструктурные вопросы сеньору (могут спросить отдельно)

- **Микрофронтенды**: когда оправданы (независимые команды/релизы), подходы (Module Federation, iframe, web components), цена — дублирование зависимостей, консистентность UX, сложность инфраструктуры. Честный ответ: чаще НЕ нужны, монорепо + модульность решают.
- **Монорепо**: Turborepo/Nx, шаринг ui-kit и конфигов, инкрементальные билды.
- **Дизайн-система**: токены, компонентная библиотека, версионирование, Storybook.
- **Тестирование**: пирамида — unit (Vitest/Jest) → компонентные (Testing Library: тестируем поведение, не реализацию) → e2e (Playwright) критических сценариев. MSW для моков сети.
- **CI/CD и качество**: линт/типы/тесты в PR, preview-деплои, bundle-size бюджеты, feature flags, canary-релизы, мониторинг (Sentry, RUM-метрики CWV).
