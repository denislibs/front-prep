# Функции: приёмы, которые спрашивают на собеседовании

Половина живого кодинга на senior-собеседовании — это «напишите `debounce`», «напишите `memoize`», «реализуйте `bind`». Задачи известны заранее, решения есть в интернете, и всё равно кандидаты сыпятся. Причина простая: выученное наизусть решение разваливается от первого уточняющего вопроса — «а если у функции есть аргументы?», «а если её вызывают как метод?», «а как отменить отложенный вызов?».

Поэтому здесь всё строится по шагам: наивная версия, потом ломающий её случай, потом починка. Цель — научиться выводить решение на месте, а не вспоминать его.

Предполагается, что механику замыканий и `this` ты уже посмотрел в статьях [область видимости и замыкания](./scope-and-closures) и [this и контекст вызова](./this-and-context) — здесь они рабочий инструмент, а не тема разбора.

## Часть 1. Функция — это значение

В JavaScript функция — обычный объект особого вида. Её можно положить в переменную, передать аргументом, вернуть из другой функции, хранить в массиве, добавить ей свойство.

```js
function greet() {}
greet.version = '1.0';        // функции можно навесить свойство
console.log(typeof greet);    // 'function'
console.log(greet instanceof Object);  // true
```

Это называется **функции первого класса** (first-class functions), и из этого одного факта растёт всё остальное в статье: колбэки, каррирование, композиция, декораторы. Без него `array.map(fn)` был бы невозможен.

### Объявление против выражения

```js
declared();     // работает
function declared() {}

expressed();    // TypeError: expressed is not a function
var expressed = function () {};

arrowed();      // ReferenceError: Cannot access 'arrowed' before initialization
const arrowed = () => {};
```

**Объявление функции** (function declaration) поднимается целиком: движок на этапе создания области видимости заводит имя и **сразу** кладёт в него готовую функцию. Поэтому вызвать можно выше по коду.

**Функциональное выражение** (function expression) — это создание значения и присваивание. Поднимается только переменная. С `var` она поднимается со значением `undefined` (отсюда `TypeError`: пытаемся вызвать `undefined`), с `let`/`const` — попадает во **временную мёртвую зону** (temporal dead zone), и обращение до строки объявления кидает `ReferenceError`.

Практический вывод: объявления удобны для «вспомогательных функций внизу файла», но именно они создают неочевидный порядок чтения. В условных блоках объявления вообще ведут себя по-разному в строгом и нестрогом режимах — там надёжнее выражения.

Есть ещё **именованное функциональное выражение**:

```js
const fact = function f(n) {
  return n <= 1 ? 1 : n * f(n - 1);   // f видно только внутри
};
```

Имя `f` доступно только внутри тела. Полезно для рекурсии, которая не сломается, если переменную `fact` переприсвоят.

## Часть 2. Параметры

### Значения по умолчанию

```js
function connect(url, { retries = 3, timeout = 5000 } = {}) { }
```

Три детали, которые проверяют:

1. **Значение по умолчанию подставляется только для `undefined`.** `null` считается переданным значением: `connect(url, null)` упадёт, потому что деструктурировать `null` нельзя.
2. **Выражение вычисляется при каждом вызове**, а не один раз. Поэтому `function f(arr = [])` безопасно — новый массив каждый раз, общего состояния нет (в отличие от известной ловушки Python).
3. **Параметры видят друг друга слева направо**: `function f(a, b = a * 2)` работает, а `function f(a = b, b)` — нет.

### Остаточные параметры

```js
function sum(first, ...rest) {   // rest — настоящий массив
  return rest.reduce((acc, n) => acc + n, first);
}
```

Остаточный параметр (rest) собирает все оставшиеся аргументы в массив. Он должен быть последним, и только один.

### arguments и почему его не используют

`arguments` — псевдомассив со всеми аргументами, доступный внутри обычной функции. Причин отказаться четыре:

1. **Это не массив.** Есть `length` и индексы, но нет `map`, `filter`, `reduce`. Приходится писать `Array.prototype.slice.call(arguments)`.
2. **В стрелочных функциях его нет.** Стрелка берёт `arguments` из внешней функции, как и `this`.
3. **Не видно из сигнатуры.** `function f()` с использованием `arguments` — функция, у которой в объявлении нет параметров, а на деле она их принимает. Читать невозможно.
4. **Мешает оптимизации.** В нестрогом режиме `arguments` связан с параметрами: изменил `arguments[0]` — изменился и первый параметр. Движку это стоит дорого.

`...rest` решает всё это разом.

### length и name

```js
function f(a, b, c = 1, ...rest) {}
f.length;   // 2 — считаются параметры ДО первого со значением по умолчанию
f.name;     // 'f'

const g = () => {};
g.name;     // 'g' — имя выводится из переменной

const h = (() => {}).bind(null);
h.name;     // 'bound '
h.length;   // 0 — bind вычитает переданные аргументы
```

`length` — **арность** функции: сколько объявлено обязательных параметров. Остаточные и параметры со значениями по умолчанию не считаются. На этом свойстве строятся библиотеки каррирования: они смотрят на `fn.length`, чтобы понять, когда аргументов достаточно.

`name` полезно для отладки и логов; движок выводит его из присваивания, а `bind` добавляет префикс `bound `.

## Часть 3. Чистые функции

**Чистая функция** (pure function) — та, которая удовлетворяет двум условиям:

1. При одних и тех же аргументах всегда возвращает одинаковый результат.
2. Не имеет **побочных эффектов** — не меняет ничего вне себя: не мутирует аргументы и внешние переменные, не пишет в DOM, не отправляет запросы, не логирует.

```js
// Нечистая: мутирует аргумент
function addItem(cart, item) { cart.push(item); return cart; }

// Чистая: возвращает новый массив
function addItem(cart, item) { return [...cart, item]; }
```

### Почему это критично для React

React строит работу на предположении о чистоте:

- **Сравнение по ссылке.** `React.memo`, `useMemo`, зависимости `useEffect` сравнивают значения через `Object.is`. Если функция мутирует массив на месте, ссылка не изменилась — React считает, что ничего не поменялось, и не перерисовывает. Отсюда правило «не мутируй состояние».
- **Функция компонента может быть вызвана лишний раз.** В строгом режиме разработки React вызывает рендер дважды именно чтобы вскрыть побочные эффекты. Конкурентный рендер может начать рендер, бросить и начать заново.
- **Мемоизация имеет смысл только для чистого.** Кешировать результат нечистой функции нельзя — эффект не воспроизведётся.

Ещё чистые функции тривиально тестируются: подал вход, сравнил выход, никаких моков. Про то, какие методы массивов мутируют, а какие возвращают копию, — в статье [массивы, объекты и иммутабельность](./arrays-objects-immutability).

## Часть 4. Функции высшего порядка

**Функция высшего порядка** (higher-order function) — та, которая принимает функцию аргументом или возвращает функцию. `map`, `filter`, `reduce`, `addEventListener`, `setTimeout` — все они такие.

Отдельный подвид — **декоратор**: функция, которая берёт функцию и возвращает её же, но с добавленным поведением. Все примеры второй половины статьи (`debounce`, `throttle`, `memoize`, `once`) — декораторы, и все они строятся по одному шаблону:

```js
function decorate(fn) {
  // здесь живёт состояние декоратора
  return function (...args) {
    // что-то делаем до
    const result = fn.apply(this, args);   // вызываем оригинал
    // что-то делаем после
    return result;
  };
}
```

Запомни этот каркас — из него выводится всё остальное. Ключевые места: состояние в замыкании, `...args` для прозрачной передачи аргументов, `fn.apply(this, args)` для сохранения контекста.

## Часть 5. Каррирование и частичное применение

**Частичное применение** (partial application) — зафиксировать часть аргументов и получить функцию, ждущую остальные.

**Каррирование** (currying) — превратить функцию от N аргументов в цепочку функций по одному аргументу: `f(a, b, c)` становится `f(a)(b)(c)`.

Наивная реализация каррирования для трёх аргументов:

```js
const curry3 = (fn) => (a) => (b) => (c) => fn(a, b, c);
```

Универсальная версия, которая принимает аргументы и по одному, и пачками:

```js
function curry(fn) {
  return function curried(...args) {
    // Аргументов хватает — зовём оригинал
    if (args.length >= fn.length) return fn.apply(this, args);
    // Не хватает — запоминаем и ждём остальные
    return (...next) => curried.apply(this, [...args, ...next]);
  };
}

const log = curry((level, module, message) => `[${level}] ${module}: ${message}`);
const warn = log('warn');
const warnAuth = warn('auth');
warnAuth('token expired');   // '[warn] auth: token expired'
```

Здесь и виден смысл `fn.length`: он говорит, сколько аргументов ждать.

### Зачем это на практике

Учебные примеры про `add(1)(2)(3)` бесполезны и потому вредны — они создают ощущение, что приём надуманный. Реальные применения такие:

**Конфигурация перед использованием.** Заранее зафиксировали настройки, дальше работаем с простой функцией:

```js
const request = curry((method, base, path) => fetch(base + path, { method }));
const get = request('GET');
const api = get('https://api.example.com');
api('/users');   // остаётся один понятный аргумент
```

**Готовые предикаты для методов массива.** Каррированная функция идеально ложится в `map` и `filter`:

```js
const prop = curry((key, obj) => obj[key]);
const users = data.map(prop('user'));    // вместо (o) => o.user
```

**Порядок аргументов.** Каррирование заставляет ставить «настроечные» аргументы первыми, а данные — последними. Это соглашение (data-last) делает функции пригодными к композиции.

Отдельно стоит знать: `fn.bind(null, a)` — это и есть частичное применение, встроенное в язык. Каррирование от него отличается тем, что возвращает цепочку одноаргументных функций, а не одну функцию с фиксированной частью.

## Часть 6. Композиция

**Композиция** — построение новой функции из нескольких: выход одной становится входом следующей.

```js
// pipe: слева направо, как читаем
const pipe = (...fns) => (x) => fns.reduce((acc, fn) => fn(acc), x);

// compose: справа налево, как в математике f(g(x))
const compose = (...fns) => (x) => fns.reduceRight((acc, fn) => fn(acc), x);

const slug = pipe(
  (s) => s.trim(),
  (s) => s.toLowerCase(),
  (s) => s.replace(/\s+/g, '-'),
);
slug('  Hello World  ');   // 'hello-world'
```

Требование к композиции: каждая функция должна принимать один аргумент и возвращать один результат. Отсюда естественная связка с каррированием — оно как раз превращает многоаргументные функции в одноаргументные.

`compose` существует по традиции из математики, где `f(g(x))` читается справа налево. Для чтения кода `pipe` понятнее, и в новых библиотеках он основной.

## Часть 7. Мемоизация

**Мемоизация** — кеширование результата по аргументам: одинаковый вход, один раз посчитанный выход.

### Шаг 1. Один аргумент

```js
function memoize(fn) {
  const cache = new Map();
  return function (arg) {
    if (cache.has(arg)) return cache.get(arg);
    const result = fn.call(this, arg);
    cache.set(arg, result);
    return result;
  };
}
```

Обрати внимание на `cache.has`, а не `if (cache.get(arg))`. Второй вариант ломается, когда функция вернула `undefined`, `0`, `''` или `false`: считаем, что кеша нет, и пересчитываем каждый раз.

### Шаг 2. Несколько аргументов и выбор ключа

Нужен способ превратить набор аргументов в один ключ. Самый популярный вариант — и самый плохой:

```js
const key = JSON.stringify(args);
```

Почему это плохой ключ:

1. **Порядок ключей объекта влияет на строку.** `{a:1,b:2}` и `{b:2,a:1}` дают разные строки, хотя объекты эквивалентны. Кеш промахивается.
2. **Не все значения сериализуются.** Функции, `undefined` и символы просто пропадают: `JSON.stringify([undefined, function(){}])` даёт `"[null,null]"` — два разных аргумента слились в один ключ. Коллизия.
3. **`Map` и `Set` превращаются в `{}`**, `Date` — в строку, `NaN` — в `null`, `BigInt` кидает исключение, циклическая структура кидает исключение.
4. **Это дорого.** Сериализация большого объекта может стоить дороже, чем сам вычисляемый результат. Кеш, который тормозит, — худшее из решений.
5. **Ключ держит данные.** Строка с сериализованным объектом висит в памяти вместе с записью кеша.

Разумный компромисс для нескольких аргументов — **вложенные Map**: дерево, где каждый уровень соответствует одному аргументу. Сравнение по ссылке, ничего сериализовать не нужно.

```js
function memoize(fn) {
  const root = new Map();

  return function (...args) {
    let node = root;
    for (const a of args) {
      if (!node.has(a)) node.set(a, new Map());
      node = node.get(a);
    }
    // Значение храним под уникальным ключом, чтобы не спутать с уровнем дерева
    if (!node.has(RESULT)) node.set(RESULT, fn.apply(this, args));
    return node.get(RESULT);
  };
}
const RESULT = Symbol('result');
```

Но самое честное решение — не строить универсальное. Хорошая мемоизация принимает функцию вычисления ключа:

```js
function memoize(fn, keyFn = (a) => a) {
  const cache = new Map();
  return function (...args) {
    const key = keyFn(...args);
    if (!cache.has(key)) cache.set(key, fn.apply(this, args));
    return cache.get(key);
  };
}

const fetchUser = memoize(loadUser, (user) => user.id);   // ключ выбираем осознанно
```

### Шаг 3. Где нужен WeakMap

Если единственный аргумент — объект, и кешируем мы что-то, посчитанное по нему:

```js
const layout = new WeakMap();

function measure(node) {
  if (!layout.has(node)) layout.set(node, node.getBoundingClientRect());
  return layout.get(node);
}
```

Узел удалили и отовсюду отпустили — запись из `WeakMap` исчезнет сама. С обычным `Map` узел остался бы жить вечно вместе со всем поддеревом. Подробнее про это — в статье [память, сборка мусора и утечки](./memory-and-leaks).

Ограничение: ключом `WeakMap` может быть только объект, и коллекцию нельзя обойти или очистить целиком.

### Шаг 4. Когда кеш становится утечкой

Мемоизация без выселения — это утечка с отложенным сроком. Три вопроса, которые надо задать себе и которые задают на интервью:

1. **Сколько разных ключей возможно?** Десять — можно кешировать без ограничений. Идентификатор пользователя — уже нет.
2. **Насколько тяжёл результат?** Число — терпимо. Разобранный документ на 5 МБ — нужен предел.
3. **Как долго живёт кеш?** Внутри функции-компонента — умрёт с ней. В модуле — живёт до перезагрузки вкладки.

Минимальный предел размера пишется в четыре строки: `Map` в JavaScript сохраняет порядок вставки, значит первый ключ из `keys()` — самый старый.

```js
function memoizeLimited(fn, limit = 100) {
  const cache = new Map();
  return function (...args) {
    const key = args[0];
    if (cache.has(key)) return cache.get(key);
    const result = fn.apply(this, args);
    cache.set(key, result);
    if (cache.size > limit) cache.delete(cache.keys().next().value);
    return result;
  };
}
```

Мемоизация рекурсивной функции — отдельная ловушка. Внутренние рекурсивные вызовы идут напрямую, минуя обёртку, поэтому кеш не работает. Нужно, чтобы функция звала себя через мемоизированную версию.

## Часть 8. debounce, шаг за шагом

Задача: пользователь печатает в поле поиска, а мы не хотим отправлять запрос на каждую букву.

### Шаг 1. Наивная отсрочка

```js
function debounce(fn, delay) {
  return function () {
    setTimeout(fn, delay);
  };
}
```

Это не работает: десять нажатий поставят десять таймеров, и через задержку выполнятся все десять. Мы просто отложили проблему.

### Шаг 2. Отменяем предыдущий вызов

Главная идея debounce: **каждый новый вызов отменяет запланированный предыдущий.** Значит нужно помнить идентификатор таймера — в замыкании.

```js
function debounce(fn, delay) {
  let timer = null;                    // состояние живёт между вызовами
  return function () {
    clearTimeout(timer);               // отменяем то, что было
    timer = setTimeout(fn, delay);     // планируем заново
  };
}
```

Теперь функция выполнится один раз — через `delay` после **последнего** вызова. Пока пользователь печатает без пауз, вызова не будет вообще.

### Шаг 3. Передаём аргументы

Сейчас `fn` вызывается без аргументов, а обработчику события нужен `event`.

```js
function debounce(fn, delay) {
  let timer = null;
  return function (...args) {                        // приняли
    clearTimeout(timer);
    timer = setTimeout(() => fn(...args), delay);    // передали
  };
}
```

Важно: передаются аргументы **последнего** вызова. Промежуточные теряются — это по определению.

### Шаг 4. Сохраняем контекст

Если декорированную функцию вызвать как метод объекта, внутри неё `this` должен указывать на объект. Сейчас — не указывает.

```js
const search = {
  query: '',
  run: debounce(function () { console.log(this.query); }, 300),
};
search.run();   // this === undefined: fn вызвали как обычную функцию
```

Причина: `this` определяется тем, **как функция вызвана**. При вызове `fn(...args)` внутри `setTimeout` никакого объекта слева от точки нет.

Чиним: запоминаем `this` внешней функции и вызываем оригинал через `apply`.

```js
function debounce(fn, delay) {
  let timer = null;
  return function (...args) {
    const ctx = this;                                    // 1. запомнили
    clearTimeout(timer);
    timer = setTimeout(() => fn.apply(ctx, args), delay); // 2. восстановили
  };
}
```

Здесь важны две вещи. Первая — возвращаемая функция обязана быть **обычной, не стрелочной**: у стрелки нет своего `this`, ей нечего запоминать. Вторая — внутренняя функция в `setTimeout`, наоборот, **стрелочная**: она берёт `ctx` и `args` из окружения. Если бы там была обычная функция, `this` внутри неё был бы совсем другим (в браузере — `window` или `undefined`).

Кстати, `ctx` можно не заводить: стрелка внутри `setTimeout` и так возьмёт внешний `this`. Но в явном виде понятнее, а на интервью явная строчка `const ctx = this` показывает, что ты понимаешь механику, а не скопировал.

### Шаг 5. Отмена

Отложенный вызов надо уметь отменить: компонент размонтировали, а таймер тикает и держит замыкание — это утечка, см. [память, сборка мусора и утечки](./memory-and-leaks).

```js
function debounce(fn, delay) {
  let timer = null;

  function debounced(...args) {
    const ctx = this;
    clearTimeout(timer);
    timer = setTimeout(() => { timer = null; fn.apply(ctx, args); }, delay);
  }

  debounced.cancel = () => { clearTimeout(timer); timer = null; };
  debounced.flush = function (...args) {   // выполнить немедленно
    clearTimeout(timer);
    timer = null;
    return fn.apply(this, args);
  };

  return debounced;
}
```

### Шаг 6. Вызов по переднему фронту

Иногда нужно наоборот: сработать **сразу**, а последующие вызовы в течение задержки игнорировать. Это `leading: true` — так делают защиту от двойного клика по кнопке отправки.

```js
function debounce(fn, delay, { leading = false, trailing = true } = {}) {
  let timer = null;
  return function (...args) {
    const ctx = this;
    const callNow = leading && timer === null;   // таймера нет — значит пауза кончилась

    clearTimeout(timer);
    timer = setTimeout(() => {
      timer = null;
      if (trailing && !callNow) fn.apply(ctx, args);
    }, delay);

    if (callNow) fn.apply(ctx, args);
  };
}
```

Условие `!callNow` нужно, чтобы при одиночном вызове с `leading: true` функция не выполнилась дважды.

## Часть 9. throttle, шаг за шагом

Задача другая: обработчик прокрутки вызывается сто раз в секунду, а нам достаточно четырёх.

Разница в одной фразе: **debounce ждёт паузу, throttle соблюдает интервал.** Debounce при непрерывном потоке событий не сработает ни разу; throttle сработает регулярно.

### Шаг 1. По времени последнего вызова

```js
function throttle(fn, interval) {
  let last = 0;
  return function (...args) {
    const now = Date.now();
    if (now - last >= interval) {
      last = now;
      fn.apply(this, args);
    }
  };
}
```

Это вариант «по переднему фронту»: первый вызов проходит сразу, дальше — не чаще чем раз в `interval`. Недостаток: последний вызов теряется. Пользователь остановил прокрутку в момент между тиками — финальное положение не обработали.

### Шаг 2. Со срабатыванием в конце

```js
function throttle(fn, interval) {
  let timer = null;
  let lastArgs = null;
  let lastCtx = null;

  return function (...args) {
    if (timer) {                 // окно занято — запоминаем последний вызов
      lastArgs = args;
      lastCtx = this;
      return;
    }

    fn.apply(this, args);        // первый вызов — сразу

    timer = setTimeout(function run() {
      if (lastArgs) {            // за окно что-то накопилось — выполняем
        fn.apply(lastCtx, lastArgs);
        lastArgs = lastCtx = null;
        timer = setTimeout(run, interval);   // и открываем следующее окно
      } else {
        timer = null;            // тихо — закрываем throttle
      }
    }, interval);
  };
}
```

Такой вариант вызывает функцию сразу, потом не чаще раза в интервал, и гарантированно один раз в конце с последними аргументами. Это поведение по умолчанию у `lodash.throttle`.

### Что где применять

**debounce:** поиск по мере ввода, автосохранение черновика, валидация поля, запрос подсказок, обработка `resize` (нужен только финальный размер).

**throttle:** обработка `scroll` (подсветка активного пункта оглавления, кнопка «наверх»), `mousemove` и `pointermove` при перетаскивании, отправка позиции в аналитику, ограничение частоты запросов.

Мнемоника: **debounce — «скажи, когда закончишь». throttle — «докладывай раз в секунду».**

### Ловушка с рендером

Для анимаций и любых обновлений, связанных с отрисовкой, `throttle` по времени — не лучший выбор: он не синхронизирован с кадрами. Правильнее `requestAnimationFrame` — он вызывается ровно раз на кадр, см. [как работает браузер](./browser-rendering-event-loop).

```js
function rafThrottle(fn) {
  let scheduled = false;
  let lastArgs = null;
  return function (...args) {
    lastArgs = args;
    if (scheduled) return;
    scheduled = true;
    requestAnimationFrame(() => {
      scheduled = false;
      fn.apply(this, lastArgs);
    });
  };
}
```

### Общая ловушка обоих

`debounce` создаёт **новую функцию с новым состоянием**. Значит вызывать его надо один раз, а не при каждом рендере:

```jsx
// Плохо: новый debounce на каждом рендере, состояние сбрасывается,
// и старый слушатель не снят — утечка
<input onChange={debounce(handleChange, 300)} />

// Хорошо: создаём один раз
const handle = useMemo(() => debounce(handleChange, 300), []);
useEffect(() => handle.cancel, [handle]);
```

## Часть 10. once и bind

### once

```js
function once(fn) {
  let called = false;
  let result;
  return function (...args) {
    if (called) return result;
    called = true;
    result = fn.apply(this, args);
    fn = null;          // отпускаем ссылку: замыкание больше не держит оригинал
    return result;
  };
}
```

Флаг `called` нужен отдельно от `result`: без него функция, вернувшая `undefined`, вызывалась бы повторно. Обнуление `fn` — маленькая, но правильная деталь: после первого вызова оригинал больше не нужен, и незачем держать его и всё, что он замкнул.

Встроенный аналог для событий — `{ once: true }` в `addEventListener`, см. [события DOM](./dom-events).

### bind своими руками

`bind` возвращает новую функцию с намертво привязанным `this` и, возможно, частью аргументов.

Шаг 1. Только контекст:

```js
Function.prototype.myBind = function (ctx) {
  const fn = this;                       // this — та функция, у которой вызвали bind
  return function () { return fn.apply(ctx, arguments); };
};
```

Шаг 2. Частичное применение — аргументы, переданные в `bind`, идут первыми:

```js
Function.prototype.myBind = function (ctx, ...bound) {
  const fn = this;
  return function (...args) { return fn.apply(ctx, [...bound, ...args]); };
};
```

Шаг 3. Работа с `new`. Настоящий `bind` устроен так, что при вызове привязанной функции через `new` привязанный контекст **игнорируется**: `new` создаёт свой объект. Проверить это внутри можно через `instanceof`:

```js
Function.prototype.myBind = function (ctx, ...bound) {
  const fn = this;
  function bounded(...args) {
    // Вызвали через new — this уже новый объект, ctx не нужен
    const isNew = this instanceof bounded;
    return fn.apply(isNew ? this : ctx, [...bound, ...args]);
  }
  bounded.prototype = Object.create(fn.prototype || null);   // цепочка прототипов
  return bounded;
};
```

Даже если третий шаг на собеседовании не потребуют, сама формулировка «привязанную функцию можно вызвать через `new`, и тогда привязка контекста не действует» показывает глубину понимания.

Три родственных метода стоит держать в голове рядом: `call(ctx, a, b)` — вызвать сейчас с аргументами по одному; `apply(ctx, [a, b])` — вызвать сейчас с массивом; `bind(ctx, a)` — не вызывать, вернуть новую функцию. Полный разбор правил определения `this` — в статье [this и контекст вызова](./this-and-context).

## Часть 11. Рекурсия и переполнение стека

Каждый вызов кладёт кадр на стек, а стек мал. Отсюда `Maximum call stack size exceeded` примерно на десяти-пятнадцати тысячах вложенных вызовов (точное число зависит от движка и от размера кадра). Механику стека разбирали в статье [память, сборка мусора и утечки](./memory-and-leaks).

**Оптимизация хвостовых вызовов** (tail call optimization) — приём, когда движок переиспользует текущий кадр, если рекурсивный вызов последний в функции. Она есть в спецификации ES2015, но в реальности её реализовал только Safari. Полагаться нельзя.

Значит, глубокую рекурсию нужно переписывать в цикл. Общий рецепт: **завести собственный стек в виде массива**.

```js
// Рекурсивно: упадёт на глубоком дереве
function collect(node, out = []) {
  out.push(node.value);
  for (const child of node.children) collect(child, out);
  return out;
}

// Итеративно: стек в куче, а она большая
function collect(root) {
  const out = [];
  const stack = [root];
  while (stack.length) {
    const node = stack.pop();
    out.push(node.value);
    // Кладём в обратном порядке, чтобы обход шёл слева направо
    for (let i = node.children.length - 1; i >= 0; i--) stack.push(node.children[i]);
  }
  return out;
}
```

Для линейной рекурсии (факториал, сумма списка) достаточно обычного цикла с накопителем. А если рекурсия принципиально нужна и данных много, работу можно разбить на порции и раскидать по задачам через `setTimeout` — тогда стек между порциями обнуляется, а главный поток не блокируется.

## Часть 12. Конструкторы против фабрик

**Функция-конструктор** вызывается через `new`. `new` делает четыре вещи: создаёт пустой объект, привязывает его прототип к `Constructor.prototype`, вызывает функцию с этим объектом в качестве `this`, возвращает объект (если функция не вернула свой).

```js
function User(name) {
  this.name = name;
}
User.prototype.hello = function () { return 'Привет, ' + this.name; };
```

**Фабрика** — обычная функция, возвращающая объект:

```js
function createUser(name) {
  return {
    name,
    hello() { return 'Привет, ' + name; },
  };
}
```

Сравнение по делу:

| | Конструктор / класс | Фабрика |
| --- | --- | --- |
| Вызов | обязательно `new` (класс без `new` кидает ошибку) | как обычная функция |
| Методы | в прототипе, один экземпляр на всех | своя копия у каждого объекта |
| Приватность | через `#поля` | естественно, через замыкание |
| `this` | зависит от способа вызова, теряется при передаче метода | можно не использовать вообще |
| `instanceof` | работает | не работает |
| Возврат другого объекта | нельзя (вернётся объект, а не примитив) | можно вернуть что угодно |

Практика: **фабрики удобнее там, где не нужны наследование и `instanceof`** — то есть в большинстве прикладного кода. Замыкание даёт настоящую приватность, `this` не теряется при передаче метода в колбэк, а объект можно подменить в тестах.

**Классы выгоднее там, где экземпляров тысячи**: методы лежат в прототипе в одном экземпляре, а не копируются в каждый объект. Плюс классы — общепринятое соглашение для доменных моделей и ожидаемы во многих библиотеках. Как устроен поиск метода по цепочке прототипов — в статье [прототипы, наследование и классы](./prototypes-and-classes).

## Что спросят на интервью

**Чем объявление функции отличается от выражения?** Объявление поднимается целиком и доступно до строки объявления. Выражение поднимается как переменная: с `var` — со значением `undefined`, с `let`/`const` — во временную мёртвую зону.

**Что такое `fn.length`?** Количество параметров до первого со значением по умолчанию; остаточные не считаются. Используется библиотеками каррирования.

**Почему `arguments` не используют?** Это не массив, его нет в стрелках, он не виден в сигнатуре и мешает оптимизации. Заменяется `...rest`.

**Что такое чистая функция и зачем она нужна?** Одинаковый результат при одинаковых аргументах и никаких побочных эффектов. Нужна для мемоизации, тестируемости и корректной работы React, который сравнивает значения по ссылке и может вызвать рендер повторно.

**Напиши `debounce`.** Замыкание с `timer`, `clearTimeout` при каждом вызове, `setTimeout` с `fn.apply(ctx, args)`. Обязательно упомянуть передачу аргументов, сохранение `this` и метод `cancel`.

**Чем `debounce` отличается от `throttle`?** debounce ждёт паузу и при непрерывном потоке событий не срабатывает вовсе; throttle гарантирует срабатывание не чаще раза в интервал, но регулярно. Поиск по вводу — debounce, обработка прокрутки — throttle.

**Почему `JSON.stringify` плохой ключ для кеша?** Зависит от порядка ключей объекта, теряет `undefined` и функции (это коллизии), ломается на циклах и `BigInt`, и стоит дорого — иногда дороже самого вычисления.

**Когда мемоизация становится утечкой?** Когда множество ключей не ограничено или результаты тяжёлые, а кеш живёт всё время работы вкладки. Лечится пределом размера, сроком жизни или `WeakMap` для объектных ключей.

**Реализуй `bind`.** Сохранить `this` внешнего вызова как саму функцию, вернуть новую функцию, склеивающую связанные и новые аргументы через `apply`. Плюс уточнение про `new`: при вызове через `new` привязанный контекст игнорируется.

**Как переписать глубокую рекурсию?** Явный стек в массиве вместо стека вызовов. Оптимизация хвостовых вызовов в спецификации есть, но реализована практически только в Safari.

**Конструктор или фабрика?** Фабрика — приватность через замыкание, нет проблем с `this`, не нужен `new`. Класс — методы в прототипе (экономия при тысячах экземпляров), `instanceof`, наследование.

## Коротко, для повторения

1. Функции — значения первого класса: их передают, возвращают, хранят и снабжают свойствами.
2. Объявления поднимаются целиком, выражения — только как переменная (`var` — `undefined`, `let`/`const` — TDZ).
3. Значения по умолчанию подставляются только для `undefined` и вычисляются на каждом вызове. `...rest` вместо `arguments`.
4. `fn.length` — арность до первого параметра со значением по умолчанию.
5. Чистая функция — детерминированная и без побочных эффектов; это основа мемоизации и корректной работы React.
6. Каркас декоратора: состояние в замыкании, `...args` наружу, `fn.apply(this, args)` внутрь.
7. Каррирование ставит настроечные аргументы первыми и делает функции пригодными для композиции; `pipe` слева направо, `compose` справа налево.
8. Мемоизация: проверять `cache.has`, ключ выбирать осознанно, `JSON.stringify` — плохой ключ, `WeakMap` — для объектных ключей, предел размера обязателен.
9. debounce = отмена предыдущего таймера, ждёт паузу. throttle = соблюдение интервала, срабатывает регулярно. Оба обязаны передавать аргументы, сохранять `this` и уметь отменяться.
10. `debounce` создавать один раз, а не на каждом рендере, иначе состояние сбрасывается и остаётся утечка.
11. Для визуальных обновлений вместо throttle по времени — `requestAnimationFrame`.
12. `bind` = новая функция с привязанным `this` и частью аргументов; через `new` привязка контекста не действует.
13. Глубокая рекурсия переписывается в цикл с явным стеком: на TCO рассчитывать нельзя.
14. Фабрика — приватность и никакого `this`; класс — общий прототип и `instanceof`.
