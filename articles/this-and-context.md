# this, контекст вызова и стрелочные функции

С `this` происходит обидная вещь: слово знакомое, интуиция подсказывает «это текущий объект», и в девяти случаях из десяти интуиция угадывает. А потом метод передают в `setTimeout`, и всё разваливается — с сообщением вида «Cannot read properties of undefined».

Причина в одном свойстве языка, которое стоит выучить дословно:

> `this` — не переменная и не часть функции. Это **скрытый параметр**, который подставляется **в момент вызова**. Одну и ту же функцию можно вызвать пятью способами и получить пять разных `this`.

Всё остальное в JavaScript работает лексически — переменные находятся по месту, где код написан (разбор в статье [область видимости и замыкания](./scope-and-closures)). А `this` — единственное заметное исключение: он определяется динамически. Отсюда вся путаница.

## Часть 1. Что такое контекст вызова

Когда движок вызывает функцию, он создаёт для вызова **окружение** (запись со всеми локальными переменными) и кладёт туда, помимо параметров, ещё две служебные вещи: `this` и `arguments`. Значение `this` целиком определяется **формой вызова** — тем, как записана строчка с круглыми скобками.

```js
function whoAmI() {
  return this;
}

const obj = { whoAmI };

whoAmI();            // одна форма вызова
obj.whoAmI();        // другая форма — другой this
new whoAmI();        // третья
whoAmI.call('abc');  // четвёртая
```

Функция одна. `this` разный. Значит, чтобы ответить на вопрос «чему равен `this`», смотреть надо не на объявление функции, а на **строку вызова**.

### Правило 1. new

`new` перед вызовом создаёт новый объект и делает его значением `this`. Что именно там происходит по шагам — разбирается в статье [прототипы, наследование и классы](./prototypes-and-classes), здесь важен только результат.

```js
function User(name) {
  this.name = name;      // this — свежесозданный объект
}
const u = new User('Аня');
u.name;                  // 'Аня'
```

Забыл `new` — и в нестрогом режиме `this` станет глобальным объектом, а `this.name = name` тихо создаст глобальную переменную `name`. Именно из-за этой ловушки функции-конструкторы принято писать с большой буквы, а сегодня — заменять на `class`, где вызов без `new` бросает ошибку.

### Правило 2. Явная привязка

`call`, `apply` и `bind` задают `this` напрямую. Это правило сильнее вызова через точку.

```js
function greet() { return 'Привет, ' + this.name; }

const anya = { name: 'Аня' };
const boris = { name: 'Борис' };

greet.call(anya);                  // 'Привет, Аня'
greet.call(boris);                 // 'Привет, Борис'
anya.greet = greet;
anya.greet.call(boris);            // 'Привет, Борис' — точка проиграла call
```

### Правило 3. Вызов через точку

Если слева от скобок стоит `obj.method`, то `this` — это `obj`. Причём **объект до последней точки**.

```js
const app = {
  name: 'приложение',
  nested: {
    name: 'вложенный',
    show() { return this.name; },
  },
};

app.nested.show();   // 'вложенный' — this равен app.nested, а не app
```

Работает и запись через квадратные скобки: `app['nested'].show()` — то же самое.

Тонкость, которая ломает интуицию: `this` определяется **выражением вызова целиком**, а не тем, где функция лежит. Стоит оторвать метод от объекта — и правило перестаёт применяться:

```js
const show = app.nested.show;   // просто взяли функцию
show();                         // undefined или ошибка: точки при вызове нет
```

Это и есть «потеря контекста». Ей посвящена целая часть ниже.

### Правило 4. Свободный вызов

Ни `new`, ни явной привязки, ни точки — работает правило по умолчанию:

- в **строгом режиме** (`'use strict'`) и внутри ES-модулей `this` равен `undefined`;
- в нестрогом режиме `this` равен глобальному объекту — `window` в браузере, `globalThis` в общем случае.

```js
function f() { return this; }

f();                       // нестрогий режим: window
// 'use strict' в начале файла:
f();                       // undefined
```

Почему `undefined` лучше: ошибка вылезает сразу и громко (`Cannot read properties of undefined`), а не превращается в тихую запись мусора в глобальный объект. Весь код, собранный сборщиком как модуль, автоматически строгий — поэтому в современном проекте свободный вызов даёт `undefined`.

Отдельно про **нестрогую упаковку**: в нестрогом режиме примитив, переданный в `call`, оборачивается в объект.

```js
function t() { return typeof this; }
t.call('abc');                    // 'object' — строка обёрнута в String
// в строгом режиме — 'string'
```

## Часть 3. Потеря контекста

### Как это выглядит

```js
const timer = {
  seconds: 0,
  tick() {
    this.seconds += 1;
    console.log(this.seconds);
  },
};

timer.tick();                  // 1 — работает
setTimeout(timer.tick, 1000);  // NaN или TypeError
```

Разбор по шагам:

1. `timer.tick` — это **выражение доступа к свойству**. Оно вычисляется прямо сейчас и возвращает саму функцию. Объект `timer` в этом значении никак не участвует: функция не «принадлежит» объекту, она просто лежит в его свойстве.
2. Полученная функция передаётся в `setTimeout` как обычный аргумент. Связь с `timer` уже потеряна — передалась ссылка на функцию, и только.
3. Через секунду событийный цикл достаёт колбэк из очереди задач и вызывает его. Форма вызова — свободная, точки нет.
4. Срабатывает правило по умолчанию. В браузере колбэки таймеров вызываются в нестрогом контексте самого таймера, поэтому `this` окажется `window` (в старых движках — объектом `Timeout` в Node). `window.seconds` — `undefined`, `undefined + 1` — `NaN`.

Та же история со всеми колбэками: `arr.map(obj.method)`, `promise.then(obj.method)`, `element.addEventListener('click', obj.method)`.

Полезно проговорить, почему язык устроен именно так. Метод в JavaScript — не то же, что метод в Java: там метод жёстко привязан к классу, здесь функция — обычное значение, которое лежит в свойстве и может лежать в десяти свойствах сразу. Раз функция одна, а объектов много, `this` физически не может быть частью функции — его приходится передавать при вызове.

### Как чинить

**Стрелка-обёртка.** Вызов остаётся с точкой, значит правило 3 срабатывает.

```js
setTimeout(() => timer.tick(), 1000);   // внутри стрелки вызов через точку
```

**bind.** Создаём новую функцию с намертво приклеенным `this`.

```js
setTimeout(timer.tick.bind(timer), 1000);
```

**Привязка в конструкторе или в поле класса.** Про это ниже, в части про классы.

Ещё одна ловушка того же рода — метод, отданный в `addEventListener` без привязки. Там правило по умолчанию не сработает: браузер сам вызывает обработчик с `this`, равным элементу, на котором висит слушатель. Получится не `undefined`, а тихо не тот объект — и отладить это сложнее.

## Часть 4. call, apply, bind

Три метода, которые есть у любой функции, потому что живут в `Function.prototype`.

```js
function intro(greeting, punct) {
  return greeting + ', ' + this.name + punct;
}
const anya = { name: 'Аня' };

intro.call(anya, 'Привет', '!');       // 'Привет, Аня!'  — аргументы через запятую
intro.apply(anya, ['Привет', '!']);    // 'Привет, Аня!'  — аргументы массивом

const introAnya = intro.bind(anya);    // не вызывает, а возвращает новую функцию
introAnya('Здравствуй', '.');          // 'Здравствуй, Аня.'
```

Отличия по пунктам:

- **`call`** — вызвать сейчас, аргументы перечислены через запятую.
- **`apply`** — вызвать сейчас, аргументы одним массивом. Раньше был незаменим (`Math.max.apply(null, arr)`), сегодня в большинстве случаев его заменяет спред: `Math.max(...arr)`. Мнемоника: **a**pply — **a**rray.
- **`bind`** — не вызывать, а вернуть **новую функцию** с зафиксированным `this`. Исходная функция не меняется.

Три вещи про `bind`, которые любят спрашивать:

**1. Он умеет фиксировать и аргументы** — это называется частичным применением.

```js
const log = console.log.bind(console, '[app]');
log('старт');    // [app] старт
```

**2. Повторный `bind` ничего не меняет.** Первая привязка окончательна.

```js
function f() { return this.tag; }
const once = f.bind({ tag: 'A' });
const twice = once.bind({ tag: 'B' });
twice();          // 'A' — вторая привязка проигнорирована
```

Причина: `bind` возвращает **экзотическую связанную функцию**, внутри которой исходная функция и её `this` уже зашиты. Второй `bind` привязывает `this` к обёртке, а обёртка свой `this` просто не использует.

**3. `new` сильнее `bind`.** Если связанную функцию вызвать через `new`, привязанный `this` игнорируется, а создаётся новый объект. Это соответствует порядку правил на схеме: `new` стоит выше явной привязки.

**4. Каждый `bind` создаёт новую функцию.** Отсюда классический баг с подписками:

```js
el.addEventListener('click', this.onClick.bind(this));
el.removeEventListener('click', this.onClick.bind(this));   // не снимет: другая функция
```

Привязанную функцию надо сохранить в переменную и передавать одну и ту же.

## Часть 5. Стрелочные функции

### У стрелки нет своего this

Это не «стрелка берёт `this` откуда-то умным способом». Это буквально: **в окружении вызова стрелочной функции ячейки `this` не создаётся вообще**. Когда внутри стрелки встречается `this`, движок ищет его так же, как обычную переменную — по цепочке областей видимости, наружу, до ближайшей обычной функции.

То есть `this` внутри стрелки подчиняется правилам области видимости, а не правилам вызова. Отсюда всё остальное.

### Почему call со стрелкой бессилен

```js
const arrow = () => this;
arrow.call({ tag: 'X' });    // вернёт внешний this, а не { tag: 'X' }
```

`call` подставляет `this` в окружение вызова. Но у стрелки в окружении просто нет места, куда это положить, — значение некуда записать, и оно игнорируется. Формально: у стрелочной функции внутреннее поле `[[ThisMode]]` равно `lexical`, и шаг подстановки `this` для неё не выполняется.

Тот же ответ работает и для `bind`: связать стрелку по `this` нельзя. Аргументы через `bind` зафиксировать можно — это отдельная механика.

### Когда стрелка спасает

Классика — колбэк внутри метода. Раньше писали `const self = this` или `.bind(this)`, теперь просто стрелку.

```js
const loader = {
  urls: ['/a', '/b'],
  cache: {},

  loadAll() {
    this.urls.forEach((url) => {
      this.cache[url] = fetch(url);   // this — тот же loader, взят из loadAll
    });
  },
};
```

Здесь `loadAll` — обычная функция, вызвана через точку, значит её `this` равен `loader`. Стрелка внутри своего `this` не имеет и находит его в окружении `loadAll`. Работает независимо от того, как `forEach` вызывает колбэк.

Сравни с обычной функцией:

```js
loadAll() {
  this.urls.forEach(function (url) {
    this.cache[url] = fetch(url);   // TypeError: this — undefined
  });
}
```

Колбэк вызывается методом `forEach` свободно, значит правило по умолчанию, значит `undefined` в строгом режиме.

### Когда стрелка ломает

**Метод объекта.** Стрелка возьмёт `this` из области, где объект **объявлен**, а не из объекта.

```js
const counter = {
  count: 0,
  inc: () => {
    this.count += 1;   // this — не counter, а внешний this (в модуле — undefined)
  },
};
```

Объектный литерал не создаёт области видимости, поэтому стрелка смотрит выше — в модуль или в глобальный код. Правило простое: **методы объекта пиши обычной функцией**.

**Обработчик на DOM-элементе, когда нужен сам элемент.**

```js
button.addEventListener('click', function () {
  this.classList.toggle('on');    // this — сам button
});

button.addEventListener('click', () => {
  this.classList.toggle('on');    // this — внешний, ошибка
});
```

Со стрелкой нужный элемент всё равно доступен через `event.currentTarget` — это даже надёжнее, потому что не зависит от формы вызова.

**Метод прототипа.** Стрелка в прототипе не получит экземпляр: `Foo.prototype.bar = () => this.x` не работает.

**Конструктор.** `new (() => {})` бросает `TypeError`: у стрелки нет внутреннего метода `[[Construct]]` и нет свойства `prototype`. Почему именно — в статье [прототипы, наследование и классы](./prototypes-and-classes).

## Часть 6. this в классах

### Тело класса всегда строгое

Код внутри `class` выполняется в строгом режиме независимо от директив. Значит потерянный контекст даёт `undefined`, а не `window` — ошибку видно сразу.

```js
class Timer {
  seconds = 0;

  tick() {
    this.seconds += 1;
  }
}

const t = new Timer();
const fn = t.tick;
fn();            // TypeError: Cannot read properties of undefined (reading 'seconds')
```

Причина та же, что и раньше: `t.tick` возвращает функцию, вызов `fn()` свободный. Методы класса живут в прототипе и точно так же не «помнят» объект.

### Потеря контекста в React

Самое частое место, где это встречается — обработчик, переданный в JSX.

```jsx
class Button extends React.Component {
  handleClick() {
    this.setState({ clicked: true });   // this === undefined при клике
  }

  render() {
    return <button onClick={this.handleClick}>Жми</button>;
  }
}
```

`this.handleClick` в `render` — это просто функция. React сохранит её и вызовет позже, без объекта слева от точки. Три решения, в порядке появления в истории:

**1. Привязка в конструкторе.** Долгое время была канонической.

```jsx
constructor(props) {
  super(props);
  this.handleClick = this.handleClick.bind(this);
}
```

Что тут происходит: `bind` создаёт новую функцию с приклеенным `this` и кладёт её в **собственное свойство экземпляра**. При обращении `this.handleClick` движок находит собственное свойство раньше, чем метод прототипа, — прототипный метод оказывается затенён.

**2. Стрелка прямо в JSX.**

```jsx
<button onClick={() => this.handleClick()}>Жми</button>
```

Работает, но на каждый рендер создаётся новая функция. Для обычной кнопки это неважно, а для дочернего компонента в `React.memo` — важно: новый проп на каждом рендере ломает мемоизацию.

**3. Поле класса со стрелкой** — современный вариант.

```jsx
class Button extends React.Component {
  handleClick = () => {
    this.setState({ clicked: true });
  };
}
```

**Поле класса** (class field) — свойство, которое присваивается экземпляру при создании, а не кладётся в прототип. Механика ровно та же, что у привязки в конструкторе: стрелка создаётся в момент выполнения конструктора, а её внешний `this` — это `this` конструктора, то есть новый экземпляр. Синтаксис короче, а результат тот же, включая цену: у каждого экземпляра своя копия функции, вместо одной общей в прототипе.

Полезно понимать разницу для интервью: **обычный метод — один на все экземпляры, в прототипе; поле со стрелкой — своё у каждого экземпляра, зато с намертво привязанным `this`.**

В функциональных компонентах проблема исчезает: там нет `this` вообще, состояние живёт в хуках, а обработчики — обычные замыкания. Зато появляется другая — устаревшее замыкание, про которое написано в статье [область видимости и замыкания](./scope-and-closures).

### super и this

В классе-наследнике `this` нельзя трогать до вызова `super()`.

```js
class Admin extends User {
  constructor(name) {
    // this.role = 'admin';   // ReferenceError
    super(name);              // здесь создаётся this
    this.role = 'admin';      // теперь можно
  }
}
```

Причина в том, как устроено наследование: объект создаёт **самый дальний предок в цепочке**, а `super()` — это вызов родительского конструктора, который и передаёт готовый `this` вниз. До этого момента ячейка `this` в TDZ — том же состоянии, что переменная `let` до объявления.

## Часть 7. this на верхнем уровне

Значение зависит от того, чем является файл.

- **Обычный скрипт в браузере** (`<script>` без `type="module"`): на верхнем уровне `this` равен `window`.
- **ES-модуль** (`<script type="module">`, любой файл с `import`/`export`, весь код, собранный Vite или webpack как модуль): `this` равен `undefined`. Модули всегда строгие.
- **CommonJS в Node** (`require`): `this` на верхнем уровне равен `module.exports`, то есть пустому объекту. Не глобальному.

Отсюда практическое следствие: `this` вместо `window` на верхнем уровне писать нельзя — переедет код в модуль, и всё сломается. Для глобального объекта есть `globalThis`, работающий везде одинаково.

Ещё одна мелочь: в геттерах и сеттерах `this` — объект, у которого читают свойство; в статических методах класса — сам класс, а не экземпляр.

```js
class Model {
  static create() {
    return new this();   // this — сам класс Model, работает и для наследников
  }
}
```

## Что спросят на интервью

**Как определяется `this`?** В момент вызова, по форме вызова. Порядок: стрелка (берёт снаружи), `new`, явная привязка `call`/`apply`/`bind`, вызов через точку, свободный вызов.

**Чему равен `this` при свободном вызове?** `undefined` в строгом режиме и в модулях, глобальный объект в нестрогом.

**Почему `setTimeout(obj.method, 0)` теряет контекст?** Передаётся сама функция, объект в этом значении не участвует. Вызов через секунду — свободный, точки нет. Чинится стрелкой-обёрткой или `bind`.

**Чем отличаются `call`, `apply` и `bind`?** `call` вызывает сразу с перечисленными аргументами, `apply` — сразу с массивом аргументов, `bind` возвращает новую функцию с зафиксированным `this` (и, при желании, с частью аргументов).

**Что вернёт повторный `bind`?** Первую привязку: связанная функция игнорирует попытку переназначить `this`.

**Есть ли `this` у стрелочной функции?** Нет. Она ищет `this` по цепочке областей видимости, как обычную переменную. Поэтому `call` и `bind` на её `this` не влияют.

**Когда стрелка вредна?** Как метод объекта или прототипа, как конструктор, как обработчик события, если нужен сам элемент через `this`.

**Почему в React-классах методы биндят?** Обработчик передаётся как значение и вызывается React свободно. Решения: `bind` в конструкторе, стрелка в JSX, поле класса со стрелкой.

**Чем поле класса со стрелкой отличается от обычного метода?** Метод один на все экземпляры и лежит в прототипе; поле создаётся заново для каждого экземпляра, зато его `this` привязан навсегда.

**Чему равен `this` на верхнем уровне модуля?** `undefined`. В обычном скрипте — `window`, в CommonJS — `module.exports`.

## Коротко, для повторения

1. `this` — скрытый параметр вызова, а не часть функции. Смотри на строку вызова, а не на объявление.
2. Порядок правил: стрелка → `new` → `call`/`apply`/`bind` → вызов через точку → правило по умолчанию.
3. Правило по умолчанию: `undefined` в строгом режиме и модулях, глобальный объект в нестрогом.
4. При вызове через точку `this` — объект до **последней** точки.
5. Оторвал метод от объекта — потерял контекст. Это касается любых колбэков: таймеров, промисов, обработчиков, `map`.
6. `call` — аргументы списком, `apply` — массивом, `bind` — новая функция с приклеенным `this`. Повторный `bind` бесполезен, `new` сильнее `bind`.
7. Каждый вызов `bind` даёт новую функцию — снять обработчик другой привязкой не получится.
8. У стрелки нет своего `this`, `arguments` и `prototype`, её нельзя вызвать через `new`.
9. Стрелка хороша как колбэк внутри метода и плоха как метод объекта, метод прототипа или обработчик, которому нужен элемент.
10. Тело класса всегда строгое. Метод, оторванный от экземпляра, даёт `undefined`, а не глобальный объект.
11. Поле класса со стрелкой = метод с навсегда привязанным `this`, ценой отдельной копии на каждый экземпляр.
12. На верхнем уровне модуля `this` — `undefined`. Для глобального объекта есть `globalThis`.
